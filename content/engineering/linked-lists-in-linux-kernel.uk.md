У ядрі Linux уже давно реалізовані готові зв'язні списки, тож під час написання модулів ядра чи драйверів вигадувати власні велосипеди не потрібно. Проте інтерфейс роботи з ними дещо незвичний після класичних курсів CS. Усі операції описані в заголовному файлі `include/linux/list.h`.

Головна відмінність від класичного підходу: у стандартних структурах даних елемент списку зазвичай містить вказівник на дані (`node->data = my_data`). В ядрі Linux усе зроблено навпаки: службова структура списку (`struct hlist_node` або `struct list_head`) інкапсулюється **всередину** вашої структури даних як одне з її полів. Завдяки макросу `container_of` (обчислення зміщення структури в пам'яті через `offsetof`) ядро знаходить адресу батьківської структури без зайвих виділень пам'яті під вузли-обгортки.

Спочатку оголошуємо та ініціалізуємо голову списку (хеш-списку `hlist`):

```c
struct hlist_head inodes;
INIT_HLIST_HEAD(&inodes);
```

Далі оголошуємо структуру, екземпляри якої будуть елементами цього списку:

```c
struct ffs_inode_info {
    struct inode vfs_inode;
    struct ffs_fd fd;
    struct hlist_node list_node;
    struct buffer_head *datablock;
};
```

Щоб структура могла стати частиною списку, вона обов'язково повинна містити поле типу `struct hlist_node`. Спочатку це може спантеличити, адже зазвичай очікуєш, що елементи зв'язного списку зберігають вказівники на елементи свого ж типу.

### Додавання елемента в голову списку

```c
struct ffs_inode_info *finode;
/* ... виділення пам'яті та ініціалізація finode ... */

hlist_add_head(&finode->list_node, &inodes);
```

### Видалення елемента зі списку

```c
hlist_del(&finode->list_node);
```

### Ітерування по списку

Для проходження по всіх елементах списку використовується макрос `hlist_for_each_entry`:

```c
struct hlist_head *head = &inodes;
struct ffs_inode_info *i;

hlist_for_each_entry(i, head, list_node) {
    /* обробка поточного елемента i */
}
```

Такий підхід забезпечує максимальну ефективність кешу процесора та усуває накладні витрати на динамічне виділення пам'яті під службові вузли.
